## O que é um Junior Dev e o que se espera dele

### O que é um Júnior Dev?

- Desenvolvedor junior é um profisisonal, e como um profissional é esperado que ele consiga fazer código profisional.
- Vaga de junior não é uma vaga de estágio, é uma vaga de um profisisonal.
- Junior não é sinônimo de amador, junior não é sinônio de "eu não sei o que eu estou fazendo", junior não é sinônimo de "eu vou aprender", junior é sinônimo de
"eu tenho pouca experiência." Se a pessoa não possui experiência nenhuma, então ela não pode trabalhar como um profissional, ela precisa adquirir essa experiência
fazendo algum tipo de projeto para que ela consiga interagir com código de verdade, com sistemas reais.
- Por essa razão, não é possível trabalhar como dev junior sem experiência, mas é possível trabalhar como dev junior tendo experiência em projetos pessoais,
  em projetos open source, projetos de faculdade, etc.
- O que não é aceitável é você nunca ter trabalhado com código de verdade na vida e querer entrar no mercado como dev junior.

### O que se espera de um Júnior Dev?

- Que ele tenha domínio de pelo menos uma linguagem de programação;
- Que ele tenha domínio de pelo menos um framework;
- Que ele saiba como funciona uma comunicação básica entre cliente e servidor (HTTP, request, response, status code, etc);
- Já tenha no mínimo entrado numa interface de um banco de dados e tido uma experiência de inserir, consultar, deletar e atualizar dados;

## Construindo uma compreensão básica de como funciona o trabalho de um junior e o que engloba ou não engloba seu trabalho

Por exemplo, em algum momento é interessante que um junior já tenha tido contato com um banco de dados (geralmente um SQL), como MySQL, Postgres, etc.
É esperado que ele entenda um pouco de SQL quer dizer que um junior já tenha aberto 1x na vida alguma ferramenta de visualização de banco de dados (datagrip, dbeaver, pgadmin, etc.) e já tenha feito algumas queries nesse DB (e.g Select * from users where id = 1;).
Não é esperado que um junior necessariamente seja um expert em otimização de queries (se você foi um expert em otimização de queries, você não é alguém junior, pelo menos
ao que tange a área de DBs).

### Começando falando especificamente da linguagem

Esse aqui é o cinequanon (condição indispensável) para se tornar um desenvolvedor, sem a compreensão e até certo domínio de uma linguagem, não é possível que você consiga
um emprego de junior na área, pelo menos no mercado atual. É quase impossível conseguir.

#### O que é o domínio de uma linguagem?

Supondo que você vai escolher Python para trabalhar. Python vai ter algumas estruturas básicas, como:

- Classes

- Dict, etc.

Então conhecimento básico de uma linguagem engloba aquilo que é mais comumente usado aquilo para o qual a linguagem mais é utiliza ou no backend ou no frontend a depender área
que você deseja trabalhar.

- Dentro dessa uma linguagem, tem aquilo que é o conhecimento do básico do básico do básico.
- Conhecer algumas estruturas de dados;
- Conseguir utilizar a lógica de programação de fato;
- OOP / SOLID -> isso no mundo real vai se traduzir em conseguir lidar com classes, lidar com interfaces, etc.

programinha que consegue fazer algum calculo, uma funçãozinha que consegue fazer alguma manipulação de string (e.g. pegar o ultimo nome de alguém, formatar um CPF, etc.)

#### Arrays

- O que são arrays:
Arrays são estruturas de dados que permitem armazenar uma coleção de valores em uma única variável. Eles são indexados por números inteiros, começando em 0.
O que um array me permite fazer:
- Adicionar itens
- Remover itens
- Ordenar itens
- Iterar sobre os itens
- Armazenar valores heterogêneos (strings, numbers, objects, arrays, etc.)
- Pode ser criado de forma dinamica (tamanho varia conforme necessidade)
- Pode ser criado dentro de objetos.
- É uma estrutura de dados linear, o que significa que seus elementos são armazenados em uma sequência ordenada. E geralmente o tamanho é fixo.
- Pode ser criado dentro de outros arrays.

Exemplos:

const arr = [1, 2, 3];

console.log(arr);

arr.pop(); // o pop tira o ultimo item do array

console.log(arr);

arr.push(4); // adiciona o item na ultima posição do array

console.log(arr);

arr.shift(); // retira o primeiro item do array

console.log(arr);

arr.unshift(0); // insere o item na primeira posição do array

console.log(arr);

arr.sort(); // ordena o array (do menor para o maior)

console.log(arr);

arr.reverse(); // inverte a ordem do array

console.log(arr);

arr.length; // retorna o tamanho do array

console.log(arr.length);

arr.splice(1, 1); // remove um item do array

console.log(arr);

arr.splice(1, 1, 5); // remove um item do array e adiciona um item no lugar

console.log(arr);

arr.slice(1, 1); // retorna um novo array com um item do array

console.log(arr);

Exemplo:
Vamos imaginar que queremos fazer um filtro. Filtrar pizzas que custem <= 40 reais. É pra ser algo relativamente fácil. E pra conseguir fazer isso, é necessário
ter um certo domínio, precisa ter brincado o suficiente com essa linguagem, com esse tipo de probleminha pra conseguir resolver isso daqui.

Aqui entra na parte de lógica de programação, que como eu já disse anteriormente, é a base de tudo. É preciso conseguir usar for lops, if elses, etc., esse tipo de coisa,
pra de fato conseguir fazer as coisas.

Qual a computação que precisamos fazer pro exemplo (sendo o filtro do custo das pizzas <= 40):

const produtosAcima40 = [];

for (let i = 0; i < produtos.length; i++) {
    const produto = produtos[i];
    if (produto!.preco >= 40) {
        produtosAcima40.push(produtos);
    }
}

console.log(produtosAcima40);

Você, como um programador que tem algum tipo de experiência, vai ver o objetivo e começar o raciocínio (e.g. "Bom, vou iterar por todos os produtos, vou checar

Pronto, isso é um exemplo simples em cima de um algoritimo, em cima de uma estrutura de dados.

Só que existe uma forma melhor de fazer isso, usando o filter

const produtos30Acima = produtos.filter(produto => {
    return produto!.preco >= 30;
})

console.log(produtos30Acima);

## O que é uma API?

Muito do trabalho de um dev junior é construir ou consumir api's.

API é uma Interface de Programação de Aplicações, em inglês Application Programming Interface. É um conjunto de regras e protocolos que permite que diferentes
aplicativos se comuniquem entre si. É uma forma de compartilhar dados e funcionalidades entre diferentes sistemas.

APIs são usadas em diversos cenários, como por exemplo, em sistemas bancários, redes sociais, sistemas de pagamento, etc. Elas são usadas para integrar diferentes
sistemas e permitir que eles se comuniquem entre si.

A gente utiliza api's para ou expor algo que pode ser acessado por outros serviços, ou a gente consome api's de outras pessoas. É um jeito de programas conversarem
com outros programas.

Esse conhecimento de api's é fundamental para um web dev junior. Você não consegue ser um web dev se você não entender como funciona uma api.

## O que é um protocol http?

Uma api, no mundo real, na maioria do casos, recebe algum tipo de request via network, via rede. Então, espera-se também que você entenda o básico de protocols de
comunicação como http.

Um protocol http é um conjunto de regras que define como os computadores se comunicam entre si na internet. É um protocol de requisição e resposta, ou seja, um
cliente envia uma requisição para um servidor, e o servidor envia uma resposta para o cliente.  

Entender o que é uma requisição, o que é uma response, o que é um header, o que é um body, etc. É importante entender o que é uma rota, o que é um método http, etc.
Não precisa ser um expert, mas precisa ter um conhecimento basico disso.

Não necessariamente é um protocolo http ou https, pode ser outros tipos de protocol (e.g. soap, gRPC, etc). Mas no mundo moderno, o protocolo http é o mais utilizado.

## Frameworks

Bom, o Galego afirma, que em toda a carreira dele (sendo hoje um CTO e tendo mais de 10 anos de experiência), que ele nunca viu um backend sendo codado na mão. Ou seja, sem framework. Nunca nunca viu um backend de verdade, em produção, que serve uma aplicação sendo construída "do zero". Logo, temos que escolher, além de uma linguagem, um framework.

Um framework é um conjunto de ferramentas, bibliotecas e convenções que auxiliam no desenvolvimento de software. Ele fornece uma estrutura básica para o desenvolvimento de aplicações, o que facilita o trabalho dos desenvolvedores. Ou seja, um framework é um conjunto de ferramentas, bibliotecas e convenções que permite que não tenhamos que reinventar a roda. Se não, teriamos que codar muita coisa na mão para fazer algo simples, como expor uma api, por exemplo. Como tem pessoas que trabalham e expoem api's o dia inteiro o tempo
tempo, a gente pode depender e construir em cima desse trabalho que já foi feito antes para que não tenhamos que reinventar a roda.

É importante ressaltar que um framework não é uma solução mágica, ele não vai resolver todos os problemas. É apenas uma ferramenta que vai auxiliar no desenvolvimento de software.

É como se fosse um conjunto de "regrar" ou "código pré-escrito" que nos ajuda a construir aplicações web mais rapidamente e de forma mais organizada. Em vez de escrevermos tudo do zero (como lidar com requisições http, rotas, bancos de dados, etc.), o framework já nos dá "tijolos prontos" que podemos usar.

Exemplos de frameworks de backend populares:

- Express.js (Node.js)
- Django (Python)
- Ruby on Rails (Ruby)
- Laravel (PHP)
- FastAPI (Python)
- Spring Boot (Java)
- Hono (TypeScript)

## Banco de Dados (DataBases)

Um banco de dados é um sistema de gerenciamento de dados, ou seja, é um sistema que permite que a gente armazene e gerencie dados. Ele é responsável por armazenar, organizar, recuperar e gerenciar dados de forma eficiente. É um recurso fundamental para qualquer aplicação que precise armazenar dados de forma persistente.

No mundo real, os dados que a aplicação utiliza precisam ser persistidos em algum lugar. Isso pode ser em um banco de dados relacional, um banco de dados NoSQL, um arquivo, etc.

## ORMs (Object-Relational Mapping)

Um ORM é uma ferramenta que permite que a gente utilize objetos do nosso código para interagir com o banco de dados.

## GitHub e Git

O GitHub é uma plataforma de hospedagem de código-fonte que utiliza o sistema de controle de versão Git.

O Git é um sistema de controle de versão distribuído, o que significa que cada desenvolvedor tem uma cópia completa do repositório em sua máquina. Isso permite que os desenvolvedores trabalhem de forma independente e sincronizem suas alterações quando necessário.

## Docker

Docker é uma plataforma de conteinerização de aplicações. Ele permite que a gente empacote uma aplicação e suas dependências em um contêiner, que pode ser executado em qualquer ambiente que tenha o Docker instalado. O objetivo é que o ambiente onde o código será executado seja exatamente igual ao ambiente onde ele foi desenvolvido.

## CI/CD (Continuous Integration/Continuous Delivery/Continuous Deployment)

CI/CD é um conjunto de práticas de desenvolvimento de software que visa automatizar o processo de entrega de software. Ele permite que os desenvolvedores entreguem software de forma mais rápida e confiável. O que faz o CI/CD inicializar é um trigger, que pode ser um push, um commit, um merge, um pull request, etc.

## Cloud

Cloud é um termo que se refere a serviços de computação em nuvem, ou seja, serviços de computação que são oferecidos através da internet. Isso inclui servidores, armazenamento, bancos de dados, redes, software, análise, inteligência, etc. E na cloud é onde a aplicação roda. Os serviços de cloud são oferecidos por empresas como Amazon (AWS), Microsoft (Azure), Google (GCP), etc.

## Fila / Queue / Message Broker

Uma fila é uma estrutura de dados que permite que a gente armazene e gerencie dados de forma ordenada. Ela é responsável por armazenar, organizar, recuperar e gerenciar dados de forma eficiente. É um recurso fundamental para qualquer aplicação que precise armazenar dados de forma persistente.

## Auth / Authentication / Authorization (O Auth)

Auth é um termo que se refere a serviços de autenticação e autorização, ou seja, serviços que permitem que a gente autentique e autorize usuários.

Autenticação é o processo de verificar a identidade de um usuário. É como se fosse o RG ou a carteira de identidade do usuário. A autenticação verifica se o usuário é quem ele diz ser.

Autorização é o processo de verificar se o usuário tem permissão para acessar um determinado recurso. É como se fosse o passaporte ou o visto do usuário. A autorização verifica se o usuário tem permissão para acessar um determinado recurso.

## System Design / Arquitetura de Software

System design é o processo de projetar um sistema. Tipos de arquitetura: monolithica, modular, microserviço, serverless, etc.

Monolítica: é um sistema onde tudo é feito em um único local, ou seja, tudo está em um único pacote.

Modular: é um sistema onde o código é dividido em módulos, ou seja, o código é dividido em partes menores e mais fáceis de gerenciar.

Microserviço: é um sistema onde o código é dividido em serviços, ou seja, o código é dividido em partes menores e mais fáceis de gerenciar.

Serverless: é um sistema onde o código é executado em servidores que não são gerenciados pelo desenvolvedor, ou seja, o código é executado em servidores que são gerenciados por terceiros. Ex: AWS Lambda, Azure Functions, Google Cloud Functions, etc.
